# 方法论详述：七阶段 + 并行起草 + 结构化评审

本文件是 `SKILL.md` 第四节的细化，供 Agent 在 `/draft`、`/review`、`/refine` 阶段遵循。

## 1. 15 维需求解析清单（Phase 1 必扫）

写《需求摘要》前，逐维判断"已知 / 待澄清 / 不适用"，待澄清项进入 Grill-Me：

1. 目标用户与角色
2. 核心价值主张
3. 核心用户流程（主路径）
4. 数据实体与关系
5. 外部集成（登录/支付/地图/短信/IM/云存储）
6. 性能与并发预期
7. 合规与隐私（个保法/GDPR/等保）
8. 离线 / 弱网策略
9. 多端同步（若多端）
10. 鉴权与权限模型
11. 支付与交易
12. 通知（推送/站内/邮件/短信）
13. 国际化与多语言
14. 部署与运维（托管/自建/容器/Serverless）
15. 验收标准（可量化）

## 2. 并行起草切片（Phase 2）

把 PRD 拆成 5 个独立片段，各自成稿，最后拼接。每片必须包含"执行指令"小节，告诉编码 Agent 如何落地。

- **数据层**：ER 图（文字）+ 每张表字段/类型/约束/索引/种子数据。
- **接口层**：RESTful 或 RPC 端点表；统一响应信封 `{code,message,data,traceId}`；错误码字典。
- **功能层**：功能清单 → 每个功能用户故事（As a… I want… so that…）+ 验收标准（Given/When/Then）+ 边界情况。
- **界面层**：页面树 + 组件树 + 布局描述 + 交互 + 空态/加载态/错误态 + 响应式断点。
- **非功能层**：性能预算、安全控制、合规项、可观测（日志/埋点/告警）、部署架构。

## 3. 结构化评审格式（Phase 3 / 5）

每条发现按如下格式，禁止空泛：

```
[级别] 位置/主题：问题描述
  影响：…
  建议：…
  关联：[矛盾表中编号]
```

- 级别：CRITICAL（阻塞执行/安全/合规）/ HIGH（重要缺口）/ MEDIUM（体验或一致性）/ LOW（锦上添花）
- 主矛盾表：列出所有相互冲突的假设/定义，逐条给唯一裁决。

## 4. 跨切面统一表（Phase 4 建立，全文强制）

| 类别 | 唯一规范 |
| :-- | :-- |
| 命名 | 表/字段/变量/接口 蛇形 or 驼峰（二选一，统一） |
| 路径 | `/api/v1/<资源>` 风格 |
| 响应信封 | 统一 `{code,message,data,traceId}` |
| 分页 | `page+pageSize` 或 `cursor`，全站一致 |
| 删除 | 软删（含 `deleted_at`）或硬删，统一 |
| ID 生成 | 雪花 / UUID / 自增，统一 |
| 校验 | 前后端共用规则来源（Zod/JSON Schema） |
| 时间 | UTC 存储，展示时区转换 |
| 错误码 | 全局字典，不复用魔法数字 |

## 5. Grill-Me 提问模板

```
Q{n}：<问题>
  推荐：<推荐答案>
  你的选择（直接确认或给我替代）：
```

每次只抛一个 Q，拿到回答再抛下一个；可用推荐答案兜底并打 `[假设]`。
