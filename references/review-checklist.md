# 多视角评审清单（Phase 3 / Phase 5 使用）

## Review A — 架构视角（单一架构师）

- [ ] 是否存在需求缺口（某功能无数据/无接口支撑）
- [ ] 是否存在定义矛盾（同一概念两种说法）
- [ ] 是否有歧义（模糊动词、未定义术语）
- [ ] 命名是否漂移（同一实体多名称）
- [ ] 跨切面是否一致（对照 methodology.md 跨切面表）
- [ ] 功能优先级是否合理（P0 是否真最小可上线）
- [ ] 数据模型是否闭环（关系/外键/索引完整）

## Review B1 — 平台适配（对照 platform-rules.md）

- [ ] 小程序：类目资质、隐私协议、分包、开放能力（登录/支付/广告）合规
- [ ] iOS：App Store 审核指南、HIG、IAP、隐私清单、ATT
- [ ] Android：Material、商店政策、SDK 合规、权限最小化
- [ ] H5：微信 JS-SDK 域名校验、分享、浏览器兼容
- [ ] 游戏：版号/实名/防沉迷（小游戏）、性能/音效（网页小游戏）
- [ ] 多端：一致性矩阵是否覆盖

## Review B2 — 安全合规

- [ ] 鉴权：登录流程、token 存储、刷新、注销
- [ ] 越权：水平/垂直越权防护（对象级校验）
- [ ] 注入：SQL/NoSQL/命令/XXE 防护
- [ ] 密钥：AppSecret/API Key 不在前端，后端保管
- [ ] 隐私：个保法/GDPR 同意、最小收集、加密存储、脱敏展示
- [ ] 传输：全站 HTTPS、敏感接口签名/防重放

## Review B3 — UX 体验

- [ ] 可访问性 a11y：对比度、语义、键盘可达
- [ ] 空态 / 错误态 / 加载态齐备
- [ ] 弱网 / 超时 / 重试策略
- [ ] 响应式：移动/平板/桌面断点
- [ ] 反馈：操作成功/失败可见

## 结构化输出要求

- 每条发现带 `CRITICAL/HIGH/MEDIUM/LOW` 与"建议"。
- 输出主矛盾表（Contradiction Table）并逐条裁决。
- 模糊反馈（如"再完善一下"）一律驳回，要求具体。
