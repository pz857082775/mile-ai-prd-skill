# 质量门禁与反模式（Phase 7 / 第九章 / 第十章）

## 一、发布前质量门禁（/quality 逐项核实，全部通过才可 /export）

### 完整性
- [ ] 每个数据实体都有库表 schema（字段/类型/约束/索引）
- [ ] 每张表有主键、必要外键、关系说明
- [ ] 每个 API 端点有方法/路径/请求/响应/错误码/鉴权
- [ ] 每个功能有用户故事 + 验收标准（Given/When/Then）
- [ ] 每个边界情况都有处理方案
- [ ] 每个页面/组件都有布局/交互/状态描述

### 一致性
- [ ] 命名全站统一（表/字段/变量/接口）
- [ ] 路径风格统一
- [ ] 响应信封统一
- [ ] 分页策略统一
- [ ] 删除策略（软/硬）统一
- [ ] ID 生成策略统一
- [ ] 时间统一 UTC 存储

### 逻辑零错误（零容忍，必过）
- [ ] 状态机闭环：每个实体状态有合法迁移与终态，非法迁移被禁止
- [ ] 数据流闭环：每个写入都有读取/展示/回滚路径
- [ ] 权限闭环：每个敏感操作都有鉴权与越权防护
- [ ] 无矛盾：同一概念/流程前后定义一致
- [ ] 无断链：无悬空 ID、无引用不存在的实体/章节/字段
- [ ] 无逻辑描述错误（如"删除后还能查到""未登录可改他人数据"等）

### 四维评估（每个功能已标注）
- [ ] 实用性：真能解决目标用户问题
- [ ] 美观性：UI/交互体验达标（见 ui-guide.md）
- [ ] 逻辑性：自洽、可测、无矛盾
- [ ] 盈利性：对变现/增长/留存有明确贡献或可解释

### 可执行性
- [ ] 编码 Agent 无需追问即可开工（无"等等再说"）
- [ ] 所有 `[假设]` 都有推荐值且被列出
- [ ] 外部依赖（登录/支付/地图等）已指明接入方式
- [ ] 验收标准可量化、可测（Given/When/Then）

### 合规
- [ ] 第 10 章平台合规清单全部勾选或声明不适用
- [ ] 安全项（鉴权/越权/注入/密钥/隐私）已覆盖
- [ ] 隐私与数据保护符合个保法/GDPR

### 文档
- [ ] 含跨切面统一表（附录）
- [ ] 含术语表
- [ ] 含里程碑与验收标准
- [ ] 含风险与开放问题
- [ ] 无啰嗦堆话（说清楚即止，无抒情/铺垫/重复）

## 二、反模式清单（必须避免）

1. **模糊动词无量化**：写"支持搜索""优化性能"，却不定义范围与指标。→ 改为可测描述："支持按标题/标签的模糊搜索，响应 <300ms（千级数据）"。
2. **静默替用户决策**：文档里替用户假设技术栈/范围而不标注。→ 所有未确认项必须 `[假设]` 并给推荐值。
3. **单窗口串行丢细节**：一次性写完导致后段丢失前段约束。→ 用 Phase 2 并行切片。
4. **跳过平台合规**：小程序/APP 不写审核/版号/隐私。→ 强制第 10 章。
5. **契约不一致**：接口返回有时带 data 有时不带、错误码随意。→ 跨切面统一表强制。
6. **需求漂移**：同一实体中途改名、同一流程两种说法。→ Review A 抓命名漂移。
7. **功能堆砌无优先级**：把 100 个功能平铺，无 P0/P1/P2。→ 必出功能地图。
8. **验收标准像愿望**：写"用户体验好"而非可测条件。→ 用 Given/When/Then。

## 三、质量标记（完成后自评）

- 专业度：是否达到"AI 可零追问执行"
- 覆盖度：15 维是否全扫
- 合规度：平台清单是否齐
- 一致性：跨切面是否唯一

任一未达标，回到对应 Phase 修订，禁止带病交付。
